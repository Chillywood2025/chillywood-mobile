# Inactive canonical RevenueCat evidence router

This is source for local qualification, **not a deployable cutover**. It changes no existing webhook, Premium helper, grant writer, delivery endpoint, observer function or provider configuration. No worker HTTP endpoint, positive projector, hold resolver, external snapshot fetcher or live money operation is provided.

Install `core.sql`, `holds.sql`, `ownership.sql`, `worker.sql`, optional typed source bridges, then `permissions-finalize.sql`, in that order, in one explicit transaction only in a disposable qualification database. `isolated-source-bridge.sql` requires the actual isolated sandbox core and receipt modules earlier in that same transaction, with both modules' finalizers deferred until after the bridge. `legacy-source-bridge.sql` requires its explicitly named legacy source tables and stays unavailable when their replay graph is incomplete; it is not a fresh-project bootstrap. Both bridges expose only private APIs with closed runtime grants. The sources create fresh private owners/schemas and four service-only public ingress/queue RPCs. The default configuration has no connections, incomplete ownership coverage, and ingress and worker disabled. Finalizers remove temporary installer inheritance/SET and schema CREATE on new objects; installer administrative capability remains. Native tests use PostgreSQL 17.6. They do not qualify the current production owner/schema or authorize installation.

## Implemented boundary

`revenuecat-receipt-router-v1/index.ts` is a separate, disabled Edge entry point. It accepts only an exact configured Authorization value, with no alternative header/JWT fallback. This is shared-secret authentication, not a RevenueCat HMAC signature or verified store receipt. An unqualified HMAC mode is deliberately rejected. Actual provider credential/scope delivery remains unproven.

The transport reads at most 256 KiB in five seconds, rejects compressed bodies, hashes exact bytes, detects duplicate JSON keys and identity ambiguity, and encrypts the original bytes with AES-256-GCM. Authenticated additional data binds the connection revision, project, auth/key versions, raw hash and length. The worker decrypts and reparses the bytes before planning. It never logs, returns to a public client, or forwards plaintext provider payloads. Historical key revisions must be retained securely; missing keys leave work pending.

The separate default-off database ingress gate and append-only connection-revision revocations can stop intake without rewriting immutable connection identity. Ingress takes a configuration row read lock and a nonwaiting revocation-table read fence; an off transition cannot slip between its check and persistence. Gateway configuration, Edge secrets, historical key storage, operator controls and provider endpoint activation remain separately unqualified; no active transport is provisioned here.

The database preserves immutable raw parents, receipt-delivery history, reported/transfer/conflicting subjects, same-event different-byte conflict variants, exclusive catalog ownership and immutable economic original ownership. The economic original key excludes the buyer and RevenueCat project so a transfer or new reporting project cannot create a second owner. A store product cannot acquire conflicting owner generations through a different RevenueCat app/project. No generic runtime API can seed ownership from a client claim. The isolated typed importer joins actual private processed receipt/event/ingress, admitted intent/dispatch, exclusive catalog and qualified route rows with the exact authenticated raw hash. The legacy typed importer joins exact authenticated replay to its static Premium or creator source graph. Missing replay, ambiguous ownership, unsupported legacy branches and new RC purchases without a linked qualified source remain unavailable. Importing historical ownership never creates or restores a positive right.

Each transfer source and target receives a separate pending-hold child pointing to the **same** original raw evidence. It does not invent per-user hashes or write the old unique-hash quarantine table. Null/anonymous/unscopable identities remain recorded evidence, not global user holds. Known immutable original-owner mismatches preserve both reported and bound subjects. Hold records are append-only and cannot be resolved by the planner.

Malformed lists retain every independently valid identity within the raw body/JSON structure bounds, including valid siblings and unsupported transfer aliases. They remain invalid observations. Typed original admission atomically backfills earlier negatives whose reported subject was wrong or missing, appending the proven owner under the same parent. A valid, conflict-free supported terminal event may veto only its proven domain and original. Malformed/unknown/conflicting evidence remains subject-unresolved. A proven economic original can establish scope across registered aliases of the exact same store application without allowing domain narrowing; unknown originals or unqualified store applications never bridge scopes. Productless transfer never selects one Premium original or narrows by SKU.

If authenticated invalid/negative evidence cannot produce any trustworthy subject child, reads for its configured reporting project return `unavailable`. Registered aliases with the same store application/store/environment scope are also unavailable: their registry intersection proves possible economic coverage without selecting rejected JSON values. For example, duplicate sensitive keys cannot be chosen arbitrarily to infer a user or product. The raw parent remains intact; no null-user/global hold or owner is invented. Projects with no qualified economic scope intersection are unaffected. This deliberately pauses availability for the reporting project and its qualified economic aliases until reconciliation resolves the coverage gap. No reconciliation/clearance API is implemented, so operators must not activate this route while such evidence remains unresolved.

Jobs use atomic `FOR UPDATE SKIP LOCKED`, random lease IDs, monotonically increasing lease generations and a 30-second deadline. Conflicting redelivery invalidates a claimed generation. Completion requires the current lease and catalog revision; stale workers cannot complete/defer. Missing keys or unknown completion get bounded retries. Plan completion is durable planning evidence, never a provider-processed receipt. All plans must explicitly deny grants, provider dispatch, legacy projection and acknowledgement. Unknown ownership, unsupported lifecycles, ambiguous transfers and conflicting events remain pending. There is no default forwarding to the old webhook.

Until real hold enforcement and qualified projectors exist, real ingress returns HTTP 503 even after durable storage, so it does not claim the legacy system is protected. Only an exact non-conflicting `TEST` can return 200. Do not point the existing provider webhook at this endpoint or enable parallel provider delivery to it as an isolation strategy.

## Required shared integration

The new hold table and private `read_hold`/legacy veto adapters are **not enforcement of existing callers**. Their `clear` result means only no matching router veto, never valid ownership or access. `held` and `unavailable` must block the guarded consumer, and null subjects are rejected. Reads take nonwaiting shared table fences until transaction end; the outer consumer must arm its bounded timer once. A consumer must derive its full project/app/store/environment/domain/original and subject scope from qualified source mapping. The existing `revenuecat_authority_quarantined_internal(text,uuid,text)` has only provider/user/environment; OR-ing these holds into it would broaden known isolated refunds into unrelated legacy authority. Its null-user callers would also turn a subject hold into a global restriction. That replacement is intentionally absent.

The finite consumer review must cover all legacy Premium and creator grant writers, renewal/extension/restore/transfer/reconciliation paths, effective grant reads/RLS, authoring/checkout authority, watch-party paid/Premium membership and token issuance, content/digital delivery, plus the isolated runtime's copied Premium predicate graph. Merely changing the shared helper misses the isolated copy. One-time `access_grants.status='blocked'` updates do not prevent old writers resurrecting rights. Existing provider evidence and legacy history must remain intact; projection updates require separately identified effect children and replay checkpoints.

The activation blocker is different from missing implementation: a safe target installation must qualify current roles/schema and drain or fence **old function frames and direct writers**, without retrying or recreating the denied broad metadata read. That permitted process has not been established. No source test or new queue demonstrates a safe target cutover. Production maintenance, provider webhook/auth configuration, delivery-source closure and native purchase qualification require their own authorization and evidence.

## Local proof

Run `node --test tests/creator-money/revenuecat-router.test.mjs` for the exact-byte/authentication/planner/worker tests. The native entry points are `tests/router.native.mjs` (loopback port55453), `tests/isolated-source-bridge.native.mjs` (loopback port55454) and `tests/legacy-source-bridge.native.mjs` (a unique private Unix socket, TCP disabled), each taking `--local-bin /absolute/path/to/postgresql-17.6/bin`. Each runs actual source SQL in a generated local cluster and verifies shutdown/removal before success. Fixtures authenticate locally generated payloads; they are not real provider delivery, StoreKit/Play purchase, effective legacy hook coverage or production proof. Failed legacy bootstrap evidence retains the primary error and bounded redacted startup diagnostics even if cleanup also fails; uncertain cluster directories remain preserved.

The canonical validation plan and per-suite proof JSON record the exact executed group counts, source hashes and cleanup. Native coverage includes actual SQL JSONB claim → decrypt/reparse → TypeScript worker → SQL completion, concurrent claim and negative/read schedules, a 6,600-identity malformed transfer, typed source graph joins, negative-before-admission, conflicting identities, and economic alias scopes. No skipped case or source-only inspection is counted as a native pass. Independent review drove the JSONB comparison, ingress revocation, retained-identity, late-negative and scoped ambiguity regressions.
