# PaidVideo scanner and human review operations — successor v2, inactive source

This additive profile supplies an automatic bounded scanner and a separate authenticated human moderation boundary. It does not provision a worker, reviewer, object route, provider, host or release. Live money, payouts and cashout remain outside this profile. No historical production metadata read or cutover is repeated.

Install **both** `operations.sql` and then `monotonic-removal.sql` in a reviewed **fresh disabled-generation** assembly after the combined PaidVideo gateway/media candidates, within the existing `paid-video-install-grant-v2.sql`/`paid-video-install-revoke-v2.sql` interval, before `permissions-finalize.sql`. Both files are mandatory. Together they add five private FORCE-RLS tables and two public RPCs. The old public worker RPC loses its service grant, and the old private operator moderation EXECUTE grant is revoked. The authenticated reviewer RPC records identity/evidence in one already-timed transaction. The underlying legacy core function remains constrained by the database invariant even if reused internally.

This successor is self-contained apart from the original qualified `isolated-paid-video-worker/{scan,job,private-object}.mjs` dependencies. The earlier operations prototype and its ten-file manifest/proofs are preserved locally as historical evidence; they are not installation or runtime dependencies and should not be published as the repaired profile.

Removal is permanent for the immutable resource identity. A first-removal tombstone retains upload/resource/asset/incarnation/hash/object-version evidence, independently of current moderation state. Triggers cover moderation history, scan-negative upload changes, upload state, existing/new delivery assets, resource publication and offers. They serialize on the parent resource with NOWAIT, cover absence of an existing tombstone, and cannot be bypassed by an intermediate held decision, missing unpublished asset or later revision. Clearing a previously removed resource requires a new resource and separate review; this profile never restores the removed identity.

The deployment reviewer must inspect the complete assembly, final ACLs and owned install trigger. This is not an upgrade script for a populated generation. Baseline proof pins Git `12335a768fb683267ac281b1a180f9650479a98d`; new candidates and these files are hashed individually. No production objects are read or changed by manifest generation.

## Automatic worker

An operator first provisions the private route, independent verifier and scanner key, qualified native/provider configuration, and a single operations configuration. All are absent or inactive by default. The operations binding has **exactly**:

`protocol` (`scpv-operations-binding-v1`), `projectRef`, canonical `endpoint` (`https://<20-character-ref>.supabase.co`), fresh `installationId`, `sourceSha256`, `workerId`, `workerSha256`, `verifierId`, `verifierEvidenceSha256`, `configurationDigest`, `routeId`, `qualificationSha256`.

`node ops/isolated-paid-video-operations-v2/manifest.mjs` creates the reviewed source manifest and prints its canonical JSON SHA256. The operator must pin that hash on the server and in worker/reviewer configuration. It covers the runner, child, reviewer, SQL and frozen scanner/job/private-object implementation. `workerSha256` is SHA256 of `JSON.stringify(binaryHashes)` in the operator's explicitly retained property order; `binaryHashes` maps exactly `ffmpeg`, `ffprobe`, `clamscan`, `sigtool` to their executable SHA256. The worker verifies every source and binary before contact. The host must make executable/source/definition trust paths read-only to the worker; hash checks are not a substitute for host isolation.

Store configuration **outside the repository**, owned by the worker account, mode0600. Parent/state/work directories must be private mode0700, not symlinks. Configuration fields:

- `binding`, `manifest`, `sourceRoot` (the actual installed checkout), `binaryHashes`.
- `serviceToken`, `workerKeyHex` (32-byte key as64hex), `s3`: `routeId`, `bucket`, `region`, `accessKeyId`, `secretAccessKey`. These credentials are never generated, fetched, printed or included in this repository.
- `scanner`: `databaseDirectory`, `certificateDirectory`, absolute `binaries` paths. Definitions require official authenticated CVD files and detached signatures; actual ClamAV/FFmpeg execute for a positive result.
- `stateDirectory`, `workDirectory`, `deadlineMs` (1000–600000), `maxJobs` (1–16), `pollMs` (1–10000 for polling). Optional `uploadId` restricts operator recovery to one upload.

Run `node ops/isolated-paid-video-operations-v2/worker.mjs --once /private/config.json` for one queued upload. `--poll` repeats up to the configured job/deadline bound; a supervisor may start later bounded runs. An empty queue is acknowledged. Queue selection reads only this generation's pending uploads for the fixed route, one row ordered by creation/ID with `SKIP LOCKED`, excludes live leases, and authenticates its immutable object receipt before leasing. A stale creator authority holds that row rather than silently discarding content; an operator resolves its admission state before new work.

The exact lease pins the installation/source/current worker/verifier/configuration plus immutable object version. A read-only current admission check is required before every scan, including recovered leases. The subprocess pins the S3 version and enforces a hard deadline by terminating its whole process group. Actual bytes, probe, decode, malware scan and official definition authenticity produce the signed result. The server rechecks current generation/controls/worker/verifier/receipt before accepting any positive result. Signed negatives remain monotonic during retirement. No scan performs content moderation.

Every state transition first writes a private immutable `audit-<uuid>.json` record, fsyncs it, then atomically updates private `state.json` with the audit hash. Records retain exact original mutation bodies and responses and link to prior records. A restart validates its audit head. Every mutation is durable **before** HTTP dispatch. An uncertain response never causes a fresh POST, new request ID or new lease. Exit2 means unknown, interrupted scan or held current admission. A crash leaves `runner.lock`; an operator must establish that the old runner process and children are gone before removing that lock. Retain the lock inspection evidence and every audit record. Do not delete state or change binding to escape recovery. A missing mutation acknowledgement needs read-only investigation, never blind resend.

### Explicit local scan recovery

A definite local error is recorded as `interrupted_scan`; a crash may retain `scanning`. Ordinary runs hold both. The child process group is durably registered before it receives configuration or media work. The child also kills its own process group on parent IPC disconnect or its hard deadline. An explicit recovery refuses a still-running or uninspectable recorded group. The private host account/file ACL establishes local operator authority; the configured evidence hash records its approved recovery scope and is not a substitute for authentication.

1. Use `worker.mjs --scan-status /private/config.json` to read the retained state hash, exact lease/ticket, expiry, host UID and child-group identity. Investigate the cause and establish that the old runner and descendants have stopped. Correct only the local configuration issue within the same pinned binding; do not alter retained mutation/audit files.
2. Have the authorized host operator retain a mode0600 decision JSON containing `action` (`resume` or `retire`), fresh UUID `requestId`, `expectedStateSha256`, `leaseRequestId`, `ticketId`, actual `operatorUid`, `authorizationSha256` matching the separately provisioned `recoveryAuthorizationSha256` in worker configuration, `processesStoppedConfirmed:true`, a specific `reason` and `resolutionEvidenceSha256` of their retained investigation evidence.
3. `worker.mjs --resume-scan /private/config.json /private/decision.json` reads the exact original lease and checks fresh server admission, ticket expiry and current binding. It records the operator decision, then reruns the actual scanner on that same immutable version and lease. It never repeats the lease POST. Lost result acknowledgement still goes through normal exact-request recovery.
4. `worker.mjs --retire-scan /private/config.json /private/decision.json` reads the original lease and records local attempt retirement, preserving all evidence. It also accepts an exact **acknowledged lease** that never began scanning, including a held admission or crash after acknowledgement that later expired. It never accepts an acknowledged result or an unknown mutation. If the acknowledged lease retains an earlier child attempt, that process group must be proved stopped. The command sends no result and does not require working scanner binaries. It does not remove content, approve content, revoke a server lease or claim that a remote mutation had no effect. A later ordinary run can process other queued work; the server excludes the original lease until expiry. No result from the locally retired attempt is submitted by this runner.

Recovery is rejected for an `unknown` lease/result mutation, changed identity/binding, changed state, live process group, or unconfirmed original lease. Resume additionally requires the original ticket to remain current. An expired local scan may be explicitly retired while its exact historical lease remains recoverable. The previous interrupted state, original mutation journals and successful operator decision are retained as separate immutable audit records. A repeated approval cannot apply to a changed/completed/retired state. A source/installation change still needs a separate recovery plan; this mechanism does not import the historical prototype's state into a new binding.

## Human reviewer

Provision an explicitly authorized reviewer UUID and immutable authorization-evidence hash through a separately approved administrative action. No automatic entitlement, creator status, scan result or service credential grants review authority. Review uses an authenticated user's current exact Auth session and account/legal authority plus that active private allowlist. Self-review is rejected. The service role cannot call the review RPC.

Reviewer mode0600 configuration contains `binding`, `manifest`, `sourceRoot`, `stateDirectory`, `reviewerId`, `sessionId`, `userAccessToken`, `publishableKey`; media retrieval additionally requires the qualified private `s3` read configuration on the controlled review host. Do not give those host credentials to client applications. Access tokens come from the supported existing sign-in process; this tool does not fetch credentials.

Create mode0600 input JSON containing `{ "uploadId": "scpv_upload_<uuid>" }`.

1. `node ops/isolated-paid-video-operations-v2/reviewer.mjs inspect /private/reviewer.json /private/upload.json` saves a current private snapshot, including immutable media binding and last moderation decision.
2. `... reviewer.mjs media /private/reviewer.json /private/upload.json` authenticates the reviewer, fetches the exact version/hash from the qualified private origin, reauthenticates and compares the snapshot, then saves a private MP4 and an evidence template. An existing MP4 is never overwritten. This command requires clean bytes; negative moderation can proceed without fetching unsafe media.
3. The authorized human views that exact local file using the controlled review environment and supplies their decision (`clear`, `held`, `removed`), timestamp, rationale and explicit `humanReviewConfirmed:true` in the evidence packet, with `basis:"viewed_exact_media"`. For a negative report without viewing unsafe bytes, use `inspect` plus external immutable evidence and `basis:"external_report"`; the human must state that limited basis in their rationale. That basis cannot clear content. The evidence packet contains the exact snapshot, reviewer UUID and (if viewed) viewed media SHA256, and is retained privately.
4. `... reviewer.mjs decide /private/reviewer.json /private/evidence.json` sends one authenticated decision, bound to SHA256 of the exact retained evidence file. No default decision exists. The immutable server journal retains the actual user/session, authorization hash, evidence hash, media snapshot and decision.
5. On an unknown outcome use `... reviewer.mjs recover /private/reviewer.json`. It only reads the exact original decision and cannot submit another. Same-session recovery is currently required; expired/revoked sessions need a separately reviewed operator journal inspection before another decision. Do not bypass this by changing retained identity or removing state.

Snapshots become stale after any intervening media/moderation change. Decisions expire after ten minutes; revoked sessions/reviewer permissions stop use. Clear requires current active controls and clean media, and can never undo `removed`. Held/removed remain possible while the generation is retired. A scan is never human evidence.
