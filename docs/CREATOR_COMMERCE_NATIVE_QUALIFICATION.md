## Hosted execution budgets

and Database at 32 minutes 27 seconds, close to their former 25/35-minute
job caps. The integrated source adds full-schema commerce tests and native

## Prospective cohort

The external-content-link Expo module adds an Android native capability and
raises the shared Google Billing dependency to 8.2.1. Source therefore targets
prospective internal V18. Existing V17 signed binaries and runtime identities
are immutable and cannot acquire this bridge through an OTA.

The conservative `git-native-inputs/v1` snapshot includes shared local-module
metadata, so both platform cohort identities advance. This does not assert a
new iOS native payment capability. Channels remain `android-internal-v2` and
`ios-internal-v2`, with Google Play internal and TestFlight Chillywood Internal
audiences unchanged. No release, build distribution or provider activation is
authorized by this source record.

Digests in `config/release/internal-native-generation.json` are derived through
`nativeSourceSnapshot` in `scripts/ota-native-source-compatibility.mjs`. The
canonical candidate test requires the new module to exist in the tested Git
commit, not just as untracked working files. Recompute after any canonical
native input changes and verify the final committed tree before release.

## Required source gates

- Sensitive validation runs the actual disposable room inventory, payment and
  lifecycle SQL tests, plus creator-money tests and Deno checks for tip, event,
  room and Google reporting endpoints.
- Database validation resets local Supabase, executes pgTAP, then runs native
  Google reporting and room-seat race schedules alongside existing event and
  subscription concurrency checks. These are native CI requirements; local
  PGlite results do not replace them.
- Native SDK validation executes the pinned real Billing 8.2.1 Java adapter and
  JVM lifecycle tests, plus the TypeScript native-flow checks.
- Existing generated-application compilation now also requires the actual
  autolinked external-link Expo Kotlin and Java modules in Debug and Release.
  Both resolved app runtime graphs must retain RevenueCat, exactly Billing
  8.2.1 and the external-link module. These graphs are actual Gradle output,
  not a dependency text search.

## Proof boundaries

Local adapter/JVM compilation and autolinking checks do not prove a generated
Expo Kotlin bridge build, signed binary, installed-device behavior or provider
delivery. Full native compilation requires the canonical CI environment with
its already-licensed Android SDK. Physical license-tester checks must cover
eligibility denial, cancellation, eligible launch, retry, account/lifecycle
changes and native RevenueCat purchase/restore regression.

Google program enrollment, authoritative storefront and qualified cohort,
reporting and tax readiness remain separate server gates. No configuration
record is seeded to pretend Google has accepted this app. Live money and
payout readiness must not be inferred from a passing source test.

## Unimplemented qualification provisioning

### Exact program binding repair

The forward `google_external_program_capability_binding` migration adds an
immutable, private capability-to-program association. Readiness requires that
exact program and package `com.chillywood.mobile`; another current program in
the same environment cannot supply qualification. Admission retries retain the
original association, new admission selects only its bound program, and checkout
rechecks it. The association starts empty, grants no API-role writes, and does
not retroactively qualify existing configuration. Revocation/expiry denies new
authority without deleting historical transaction or refund reporting duties.

This is not enrollment verification or installed runtime attestation. Native
runtime/build/cohort qualification remains an external prerequisite for a future
reviewed issuer; arbitrary client headers or evidence strings cannot establish
it. No issuer, credential, enrollment, activation or scheduler is created.
Full-schema regression reproduces the predecessor's unrelated-package readiness
and tests exact binding, missing binding, revocation and immutable history. The
existing admission/reporting suites retain their real production SQL paths with
explicitly synthetic exact bindings; they are not Google approval receipts.

Google external-program configuration and room-auction product bindings have no
direct API-role grants, including service role. Qualified provisioning and
revocation APIs remain an activation prerequisite, not a capability conferred
by this source change. Disposable test fixtures seed synthetic configuration as
database owner and restore application roles for actual purchase/reporting
operations; RLS and immutable-fact triggers remain enabled.
