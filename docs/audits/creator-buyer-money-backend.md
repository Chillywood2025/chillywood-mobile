## Findings and repairs

| ID | Classification | Evidence / consequence | Action / remaining qualification |
|---|---|---|---|
| MB-01 | Reproducible defect, repaired | Dedicated Live Stage SQL duplicate branch (`20260901010000...`, function around line 450) returns only status/event ID/duplicate flag. Edge originally retried notifications only with intent+ledger IDs. A preference/storage failure after the purchase commit could permanently omit buyer receipt on exact retry. Existing harness always returned complete IDs and missed the contract. | Edge now recovers only notification provenance by exact provider event, buyer, environment, event type, ledger, intent, creator, source, and product. Missing/mismatched storage fails retryably. No grants/ledger/payout writes added. Four iOS/Android × access/seat cases verify sparse replay and deduplication. |
| MB-02 | Reproducible defect, repaired | Live Stage Edge writer substituted receipt time when an active provider timestamp was absent/invalid, unlike ordinary creator-money input validation. Original SQL also permitted a missing timestamp fallback. | Edge rejects active missing/invalid/nonpositive timestamp before the money RPC. Verified ingress remains recorded by the existing outer handler; this early rejection does not create a structured charge-reconciliation obligation. Twelve platform/timestamp cases prove no money RPC/notification. New SQL guard independently rejects null/nonfinite active timestamp and records an obligation when invoked directly. |
| MB-03 | Missing end-to-end feature / pricing decision | The latest `set_creator_content_price` wrapper in `20260827210000_creator_video_protected_authority_closure.sql:1141` supersedes the old range setter: it requires the exact catalog tier for `paid_content_access_sandbox_099` and USD, raising `paid_video_store_tier_not_available` for other prices. Generic checkout also requires source amount equals catalog amount. Title-room/event setters reject values other than99; VIP/channel are499. | Arbitrary prices cannot currently be saved through the public setter. Recommended supported-price catalog with provider/store/environment/version binding. No prices, revenue split, SKUs, or provider config changed. Client quoted-price validation is covered by the client agent. |
| MB-04 | Existing fail-closed behavior with recovery gap | Intents snapshot amount/currency and source. Fulfillment validates current offer against intent/provider price. Changing price/offer before webhook can reject fulfillment after store charge rather than rewrite the purchase amount. | An immutable quote/offer-version contract plus explicit reconciliation of paid-but-unfulfilled purchases is needed before flexible pricing is launched. No automatic refund promise. |
| MB-05 | Reproduced in disposable PostgreSQL; source repair included | Baseline dedicated Live Stage projector omitted ordinary creator-money current-session/quarantine/restriction checks at active fulfillment. Actual intent-binding trigger returns immediately for `consumed`. Baseline executes both actual functions with a missing issuing session: ordinary helper returns false, but projector consumes intent and writes sandbox grant/ledger. | Forward migration `20261026105832_live_stage_purchase_fulfillment_authority.sql` adds active-only checks after exact intent/provider binding and before consumption. Denied charges remain immutable ignored events, reserve their original transaction against rebinding, and create existing structured reconciliation obligations with exact reported economics. Duplicate consumed events and terminal removal remain intact. `scripts/test-live-stage-fulfillment-authority-postgres.mjs` verifies baseline failure, repair, real session trigger and real obligation capture trigger. Full-schema concurrency/deployed parity remain unproved. |
| MB-06 | Missing request-level recovery | Stripe tip checkout inserts a new random idempotency key for each request. Stripe idempotency protects retries of that one outbound request, not repeated app invocations. Three-attempt/15-second count is not transactional and is not an intent replay key. A transport/DB failure after session creation can leave an uncertain pending transaction while a retry opens a second checkout. | Define one client attempt identity bound to creator/amount/currency/session, persist/recover pending checkout, and test concurrency. Repeated voluntary tips must remain possible; do not merge this product decision with provider-event deduplication. |
| MB-07 | Implemented safety boundary, missing integration / unavailable provider evidence | Transfer-create and payout-release endpoints explicitly return preconditions-only, no provider call/write; provider settlement and payout-result receipts are revoked even from service-role writers. No receipt producer/importer was located in functions/scripts. Current settlement implementation (`20260831130000...:758`) derives platform fee as gross minus provider fee minus verified receipt creator net, rather than itself enforcing80/20. | This is not payout readiness or proof of the actual split. A trusted receipt producer must derive and verify the agreed economics before settlement. No evidence of an actual incorrect payout was observed. Keep earnings pending/not-payable until provider economics and hold/completion authority are verified. |
| MB-08 | Lifecycle notification limitation | Dedicated Live Stage terminal delivery sends refund/revocation notifications. Generic terminal dispatcher performs durable entitlement/ledger reconciliation, but does not invoke analogous buyer/creator terminal notifications for every other product mode. | Product-wide lifecycle receipt expectations require follow-up implementation/coverage; do not infer delivered communication from SQL reversal. |

## Decisions before expanded sales

1. Authoritative supported fixed-price catalog by product mode/store/environment; creator chooses from enabled prices, never an unbacked arbitrary amount.
2. Immutable purchase quote lifetime and treatment of paid-but-unfulfilled purchases after offer change, expiry, restriction, or sold-out race.
3. Explicit request-attempt recovery for external checkout; distinguish retry from an intentional repeat tip.
4. Event postponement/cancellation/no-show and replay obligations, buyer acknowledgement, reminders, provider refund workflow and responsible operator.
5. Optional auction remains design-only. Existing fixed-price IAP mapping/intent matching is not an auction settlement contract. A bid must never be treated as a payment authorization or ticket entitlement.
