# Creator/buyer paid-event backend audit

Baseline: `40c0cebb24f39afca0ae6c2ce2532ae4a56f4858` (main cloned 2026-10-26). This is a source audit in the isolated `creator-buyer-monetization` checkout. No production database, private buyer, provider purchase/refund, payout, deployment, or installed app was inspected or changed. Online shows and virtual admission capacity are the working assumption; assigned physical seating is not implemented by these tables.

Owner approval at 16:37 authorized fixed-price virtual scheduled shows; the subsequent owner decision approved recovery of late payments only when capacity and original purchased terms remain valid, otherwise visible resolution. New contract: `configure_paid_creator_event_sale(event, description, priceCents, capacityLimit, status, timeZone, salesOpenAt, salesCloseAt)` returns the offer plus `termsRevisionId`, `salesPaused`, and immutable `terms`. `create_reserved_creator_event_purchase_intent(offerId, expectedRevisionId)` returns the legacy intent plus `reservation`. `read_my_creator_event_reservation(intentId)` returns `{id,purchaseIntentId,buyerId,offerId,creatorEventId,termsRevisionId,expiresAt,state,priceCents,currency,reason,terms}`. The SDK boundary must require `held` and the exact expected identity/quote immediately before launching purchase. Expiry/unknown provider outcome is not permission to charge again.

Tables enforce RLS/FORCE RLS. Authenticated actors have only owner/session-scoped reads; anon cannot enumerate; API roles cannot insert/update/delete revisions or reservations. Internal capacity/admission/finalization helpers are not executable by API roles. The public self-read policy helper is a no-argument, empty-search-path definer that exposes only the caller's current authority boolean; it does not grant caller-selected identity inspection.

`tests/creator-money/event-reservation-authority.test.mjs` registers the complete migration-chain PGlite production-path suite in existing CI. `scripts/test-event-reservations-native-postgres.mjs --pglite` uses actual application authorization and projection functions, with only empty managed Auth/Storage schema and transport substitutes. `--container=chillywood-event-offer-audit-...` runs the same assertions against real PostgreSQL and adds actual concurrent sessions. `tests/fixtures/event-reservation-authority.sql` seeds synthetic verified creator/legal/session and sandbox-tester evidence, never mocked boolean authorization. `supabase/tests/scheduled_virtual_event_reservations_test.sql` adds focused pgTAP grants/RLS/caller checks. `scripts/export-event-reservation-runtime-fixture.mjs` exports the existing complete replay chain for the disposable native fixture.

Native first-path and continuation runs passed 38 assertions including concurrency and the negative control; two test-fixture errors were corrected (required synthetic sandbox-tester evidence and a PostgreSQL function parameter name), and duplicate receipt tests now retain the same original purchase timestamp. Final current-source rerun evidence is recorded below when complete. All container/database names are task-specific, network-isolated, without host ports or mounts; the parent's separate test fixture is preserved.
