# Cognitive Intelligence Foundation — Reviewer D Adversarial Red-Team Report

## Verdict

**Merge-readiness decision: FAIL (17 passed / 23 failed).** No P0 was found. The failures comprise **19 P1** and **4 P2** findings; there are no P3 findings.

The reviewed target is operationally safe only in its current off-state: `config/intelligence/cognitive-platform.json:4-6` declares `source_complete_not_deployed`, activation `off`, and no scheduler; the cognitive UI states that there is no model credential and only a local migration (`components/admin/cognitive-control-center.tsx:5-14`); and its controls are disabled with no handlers or RPC (`components/admin/cognitive-control-center.tsx:49-65`). Those facts contain current production risk, but they do **not** satisfy the frozen attack plan's rule that a missing enforceable contract is a failure rather than a pass.

The branch should not be represented or promoted as a source-complete cognitive platform. It may remain a non-deployed scaffold only if its status is relabeled accordingly and activation, scheduler, credentials, migration promotion, and execution wiring remain blocked. Deployment or runtime wiring is a no-go until the P1 controls are implemented and re-attacked.

The strongest implemented controls are: immutable evidence deletion protection, client-write denial/forced RLS, backend role truth, duplicate insert determinism, main-branch rejection, immutable learning-field rejection, emergency-state checking in the existing Owner Command gate, physical-evidence rejection, news corroboration, graph freshness, owner-only cognitive UI visibility, inert UI controls, and negative/overflow cost checks.

The decisive gaps are not cosmetic. The configuration describes a software executor, independent judge, capability/tool broker, model router/budget controller, and orchestrator as `source_complete_not_deployed`, but the executable foundation provides only admission helpers and prose/constants. Runtime action membership, canonical paths, symlink containment, nonce replay, platform/repository binding, per-call expiry, atomic budget consumption, loop caps, independent evidence acquisition, SSRF defense, cancellation, and rollback failure handling are absent.

Therefore:

1. **Do not deploy or promote the migration/runtime.** The off-state is doing real safety work.
2. **Do not merge under a “source complete” acceptance claim.** Either remediate the P1 controls or relabel the work as a non-executable schema/contract scaffold whose missing components are explicitly tracked.
3. **Before any activation review, rerun all 40 attacks through the real broker/executor/evaluator processes and signed PostgREST requests**, not only pure functions and direct SQL.
