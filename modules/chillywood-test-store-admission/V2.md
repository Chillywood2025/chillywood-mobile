# Registered Offering native lifetime

V2 is a separate, inactive DEBUG application: `com.chillywood.mobile.teststoredebugv2`.
Its build protocol, app storage, scheme and runtime are distinct from v1. The
checked-in profile contains no provider configuration. V1 installation records,
allocations and process admission are never migrated or reinterpreted.

The native module fixes a server-issued customer binding and provider identity
to one durable installation. The installation UUID is routing state, not device
attestation. A different buyer, configuration or captured Auth session cannot
rebind an existing process. A session retirement permanently stops new native
mutations for that process, including A→B→A. A new process may configure only the
same persisted owner. There is no SDK login, logout, restore, reset or project/key
switch operation.

Ownership and invocation records are written atomically in app-owned storage and
read back before advancing. SDK cache presence without the ownership record, or
a cached buyer identity that contradicts the owner, stops configuration. These
checks inspect pinned SDK cache keys only as negative evidence. They never adopt,
clear or log a cached identity. Android backup is disabled; iOS native records
are excluded from backup. Restore/reinstall behavior still needs actual device
qualification; a new installation UUID never proves the SDK is clean.

The lookup path holds a native process mutex while requesting CustomerInfo and
Offerings. A known completed read-only cache miss or lookup failure releases only
that lookup mutex and returns `package_unavailable`. It creates no purchase handle
or invocation record and sends no claim. A pending callback retains the mutex;
there is no timeout that declares completion. A later explicit lookup can find a
newly cached Offering. There is no same-SKU fallback or invented Package/context.

Only an exact native Offering/Package/SKU/price/currency match produces a retained
SDK Package and a durably prepared invocation. The fresh server claim must match
the complete retained customer/allocation/registration/quote and original Auth
session. After durable invocation storage and a final deadline check, the module
passes that **same Package object** to the public native purchase API. It bypasses
the hybrid bridge's package relookup without modifying the RevenueCat SDK.

Only the actual native SDK callback can commit `completed`. That commit occurs
before the JavaScript promise resolves and before the per-invocation mutex is
released. A failed completion write, lost prepared handle, or interrupted native
invocation remains blocked. JavaScript reload never reconstructs a purchase
capability. Native completion permits a later explicit invocation with the same
identity; it is not a receipt, a no-charge assertion, or proof that background SDK
posting has finished. Retained original Offering context keeps late posts tied
to the original server registration. The backend independently verifies that
binding and the authenticated receipt.

The native store retains up to 1,000 invocation records and refuses further
reservations at capacity. No cleanup or history-erasing operation is exposed.
Native reads expose the immutable invocation identity and callback observation;
receipt authority and current user authorization remain server responsibilities.

`tests/isolated-test-store-v2-native.test.mjs` has seven portable groups. Explicit
`ISOLATED_TEST_STORE_V2_NATIVE_POLICY=1` adds compiled Java and Swift Debug/Release
lifecycle tests. The required macOS native lane runs that eighth group, requires
both v1/v2 autolinked classes and all six v2 platform files, compiles the Android
Debug/Release Kotlin/Java targets and the iOS admission Pod, and records source
hashes. Local bridge compilation and policy tests do not establish installed
checkout, provider correlation, production installation or release qualification.
