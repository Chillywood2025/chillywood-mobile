# Paid Video Test Store native boundary

V3 is a separate, unconfigured DEBUG application (`com.chillywood.mobile.teststoredebugv3`). Its native profile, ownership file, server customer, allocation, registration, and provider customer IDs cannot reuse V1, V2, or qualification identities. Release builds expose no admitted configuration. The configuration digest identifies a reviewed compiled profile; it is not device attestation.

The native bridge uses RevenueCat's public `getOfferings` / `offerings` API and retains the returned Package object. It validates the registered offering identifier, package identifier, SKU, consumable type, USD price, and the complete server allocation before preparing a one-use native handle. Purchase uses that same retained Package. Provider API object IDs are never substituted for SDK lookup identifiers.

The immutable Paid Video quote includes the exact asset ID, incarnation, SHA-256, byte length, resource revision, and media profile. The persisted invocation carries that entire quote. These client/native checks do not establish media provenance, provider receipt truth, or delivery authority; those remain independently enforced server boundaries.

A known completed read-only lookup miss creates no invocation or claim and allows a later explicit lookup. Unknown lookup work retains its mutex. Preparing, invoking, and completion are durably written and read back before their corresponding results are exposed. Any persistence or readback exception permanently retires the process and prevents all subsequent writes, preserving uncertain disk evidence for a fresh process to inspect.

The RevenueCat project/key and provider customer remain fixed for the installation. Any account/session transition retires mutation authority in the current process. Cached SDK identity is only a negative consistency check, never adopted or cleared. JS reload, timeout, receipt arrival, or a cancellation report cannot manufacture native completion. A real native callback records invocation completion; it does not prove SDK quiescence, no charge, receipt verification, or access.

Default build profiles contain no provider descriptor. Actual activation still requires backend/profile/Offering/receipt/media qualification and a device rehearsal. This source does not provision a project, publish a build, install an app, or enable live money, payouts, or cashout.
